# 探索星图说明

阅读轨迹的可视化层：你在对话里聊过哪些人物、事件，会反映到一张以《雪落成诗》星云主体图为底的 ∞ 形探索星图上。

## 用户侧怎么用

1. 正常聊天（主进程 `web_chat.py` 要开着）。
2. 另开终端跑观测进程：`python user_observer.py`（或 `run_observer.bat`）。
3. 聊若干轮后，侧栏点 **阅读轨迹** → **重新生成轨迹**（或等每约 10 轮自动抽取）。
4. 点 **查看我的探索轨迹星图** 进入全屏星图。
5. **悬停人物** 可看到关联事件/意象及短线连接；未 hover 时不画连线。

Legend 上的「已点亮 N 颗 · 探索 X%」：N 为当前弧段内可见的人物数，X% 为沿 ∞ 路径已揭示的星云比例（不是全书读完百分比）。

## 它表示什么

| 元素 | 含义 |
|------|------|
| 暗场 + 淡路径 | 尚未揭示的区域 |
| 亮起弧段 | 与当前探索进度对应的星云路径 |
| 人物星点 | 对话中识别到、且落在已揭示弧段上的角色 |
| 事件/意象 | 悬停人物时在附近显示，沿路径分布，不常驻 |

人物与事件的关联来自 `数据源/关键事件链条.json` 等静态星表；一个事件可对应多个人物（`parents` 字段）。观测模块只负责「哪些被点亮」，不负责改星表拓扑。

## 两个进程各管什么

| 进程 | 职责 |
|------|------|
| `web_chat.py` | 对话、写 SQLite 事件、**打开星图时 API 实时重算** render |
| `user_observer.py` | 异步 LLM 抽取阅读轨迹，写入 `observation.db` |

观测进程用 `--reload` 开发时，改 Python 代码会生效；**改完 `static/data/exploration_star_catalog.json` 后**，主进程读星表会按文件时间刷新，一般 **Ctrl+F5 刷新页面** 即可，不必为了星表 alone 重启 observer。

若改了观测/星图 **Python 逻辑**，建议重启 `web_chat.py`；改了轨迹抽取逻辑再重启 observer。

## 数据文件（维护用）

| 路径 | 作用 |
|------|------|
| `static/data/exploration_star_catalog.json` | 人物/事件/意象节点、∞ 路径、坐标 |
| `static/images/exploration_nebula_bg.webp` | 星云底图（来自 `数据源/星图.png`） |
| `runtime_data/observation.db` | 用户 session、轨迹 state（不提交 Git） |

星表或事件链更新后，在项目根目录执行：

```bash
python scripts/resnap_starmap_paths.py
```

会从 `关键事件链条.json` 补全多人物 `parents`，并重算节点在路径上的位置。可选自检：

```bash
python scripts/audit_starmap_layout.py
# 产出 static/images/nebula_previews/starmap_layout_audit.jpg
```

从源图完整重建（换底图、重抽路径时用）：

```bash
python scripts/setup_nebula_starmap.py
# 默认读 数据源/星图.png
```

独立演示页（不依赖 session）：浏览器打开 `/static/star_map_demo.html`，需 `web_chat.py` 在跑。演示数据：

```bash
python scripts/build_starmap_demo.py
```

## 常见问题

**进度很低 / 没有星点**  
先 **重新生成轨迹**。若 LLM 抽取未填人物，系统会从你的历史提问里扫描已知人名兜底；仍为空则继续聊几轮再生成。

**星点和亮区对不齐**  
多为旧缓存：强刷页面（Ctrl+F5）。API 已改为按最新星表重算，不依赖 DB 里旧的 render 快照。

**悬停出现横穿画面的长线**  
∞ 路径在索引上相邻、在画面上可能相距很远；当前实现只连人物**附近**（路径步数 + 距离限制）的事件，避免弦线。

**预览图**  
`static/images/nebula_previews/` 下有进度预览、布点审计图、探索过程 GIF，供开发核对，用户界面不直接引用全部文件。
