# 用户观测模块与存储说明

## 技术选型结论（便宜优先）

| 方案 | 成本 | 适用 | 本项目选择 |
|------|------|------|------------|
| **SQLite 单文件（WAL）** | 免费 | 自托管单实例 FastAPI | **默认** |
| JSONL 按用户分文件 | 免费 | 极低 QPS、人工排查 | 不推荐（高写入时易碎片化） |
| Supabase / Turso 免费档 | 免费额度 | 多实例、要远程 DB | 可选升级 |
| 对象存储 S3/R2 存 JSONL | 按量极低 | 只归档、少查询 | 不适合热路径 |

**结论**：观测事件与 state 统一写入 `runtime_data/observation.db`（SQLite + WAL），主对话进程 append 事件，观测进程异步读增量。部署时将 `runtime_data/` 挂载为持久卷即可，**零额外云服务费用**。

按用户隔离：所有表带 `user_id`（Google `sub` 或 `anon_*`），查询时校验 session 归属。

## 身份验证（Google OAuth，松耦合）

- **可选**：未配置 `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` 时，使用请求头 `X-Anonymous-User-Id`（前端 localStorage 生成），适合本地开发。
- **启用 OAuth**：在 [Google Cloud Console](https://console.cloud.google.com/) 创建 OAuth 2.0 客户端（Web）。
  - 本地：`http://localhost:8000/auth/callback`
  - 公网：填 `APP_PUBLIC_URL`（后端根 URL），回调默认为 `${APP_PUBLIC_URL}/auth/callback`；须与 Google Console「已授权的重定向 URI」完全一致。

环境变量（见 `.env.example`）：

```env
APP_PUBLIC_URL=https://your-backend.example.com
GOOGLE_CLIENT_ID=xxx.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=xxx
# 可选，覆盖默认回调：
# GOOGLE_REDIRECT_URI=https://your-backend.example.com/auth/callback
AUTH_SECRET=请填随机长字符串
AUTH_COOKIE_SECURE=true   # 生产 HTTPS 时
```

API：

- `GET /auth/login` — 跳转 Google
- `GET /auth/callback` — 回调并写 httpOnly cookie
- `GET /api/auth/me` — 当前用户
- `POST /auth/logout` — 退出

## 配置

`config/observer_config.yaml`：

- `trigger_every_n_turns: 10` — 每 N 轮触发抽取
- `trigger_char_threshold: 8000` — 累计字符阈值
- `poll_interval_seconds: 15` — 观测进程轮询间隔
- `max_llm_calls_per_run: 5` — 每轮 LLM 成本上限

## 观测 API

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/observation/session` | 创建观测 session |
| GET | `/api/observation/{session_id}` | 获取阅读轨迹（`visible_summary` + `user_interest`） |
| GET | `/api/observation/{session_id}/starmap` | 探索星图 payload（实时重算 render） |
| POST | `/api/observation/trigger` | 手动触发抽取（生成轨迹与星图） |
| POST | `/api/observation/correct` | 用户修正 visible_summary |

聊天请求体新增字段：

```json
{
  "message": "...",
  "conversation_history": [],
  "session_id": "sess_xxx",
  "conversation_id": "前端对话树 ID"
}
```

响应 `final.data.observation_session_id` 回传 session，供前端轨迹面板使用。

## 公开仓库安全

- **勿提交**：`.env`、`runtime_data/`、`*.db`
- **可提交**：`config/observer_config.yaml`、代码、`数据源/user_observation_architecture.mermaid`
- 观测 DB 含用户对话内容，生产环境备份/访问需权限控制

## 升级路径（用户量增大时）

1. **仍单实例**：继续 SQLite，定期备份 `observation.db`
2. **多实例**：换 Supabase Postgres 或 Turso（改 `observation/db.py` 连接串）
3. **冷归档**：旧 session state 导出 JSON 到 R2/S3，SQLite 只保留近 90 天

当前阶段 SQLite 足够，避免过早引入付费组件。

## 轨迹与星图（当前实现）

- **文字轨迹**：`visible_summary` 2–4 句回顾；`user_interest` 含当前话题、待解追问等（前端 marked 渲染）。
- **探索星图**：以 `数据源/星图.png` 导出的星云为底，静态叙事星表（人物 / 事件 / 意象）沿 ∞ 路径布点；观测 state 决定「亮哪一段、点亮谁」。
- **打开星图时**：`GET .../starmap` 会按最新星表 **实时重算** render，不依赖 DB 里旧快照。
- **observer 写 DB**：`attach_star_map_render` 仍会落库，便于排查；以 API 返回为准。

星图交互、脚本、排错见 [探索星图说明](docs/探索星图说明.md)。
